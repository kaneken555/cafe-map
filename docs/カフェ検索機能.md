# カフェ検索機能 仕様書

## 1. 機能の目的・概要

カフェマップアプリケーションのコア機能として、ユーザーが周辺のカフェを発見し、マイマップに登録できるようにする検索機能。Google Places APIを活用し、位置情報ベースの検索とキーワード検索の2種類の検索方法を提供する。

### 主な機能
- 現在地周辺のカフェ検索（半径1km）
- キーワードによるカフェ検索
- カフェ詳細情報の表示
- 検索結果からマイマップへの登録

---

## 2. 検索機能の種類

### 2.1 位置情報ベース検索

**概要:**
地図の中心座標を基準に、半径1km圏内のカフェを検索する。

**検索仕様:**
- **検索API:** Google Places API Nearby Search
- **検索範囲:** 半径1km（固定）
- **フィルター:** タイプ = "cafe"
- **最大件数:** 約20件

**リクエストパラメータ:**
| パラメータ | 型 | 必須 | 説明 |
|-----------|---|------|------|
| lat | number | ○ | 中心地点の緯度 |
| lng | number | ○ | 中心地点の経度 |

**レスポンス例:**
```json
{
  "cafes": [
    {
      "lat": 35.6812,
      "lng": 139.7671,
      "name": "スターバックスコーヒー",
      "place_id": "ChIJ...",
      "photo_reference": "CmRaAAAA..."
    }
  ]
}
```

### 2.2 キーワード検索

**概要:**
カフェ名や地名などのキーワードで、現在地周辺のカフェを検索する。

**検索仕様:**
- **検索API:** Google Places API Text Search
- **検索範囲:** 半径1km（固定）
- **検索対象:** カフェ名、地名など
- **フィルター:** タイプ = "cafe"
- **言語:** 日本語（ja）
- **最大件数:** 約20件

**リクエストパラメータ:**
| パラメータ | 型 | 必須 | 説明 |
|-----------|---|------|------|
| q | string | ○ | 検索キーワード |
| lat | number | ○ | 中心地点の緯度 |
| lng | number | ○ | 中心地点の経度 |

**レスポンス例:**
```json
{
  "cafes": [
    {
      "lat": 35.6812,
      "lng": 139.7671,
      "name": "スターバックスコーヒー 渋谷店",
      "place_id": "ChIJ...",
      "photo_reference": "CmRaAAAA..."
    }
  ]
}
```

### 2.3 カフェ詳細取得

**概要:**
Google PlaceのIDを使用して、カフェの詳細情報を取得する。

**取得フィールド:**
- 基本情報: 名前、住所、電話番号、Webサイト
- 営業情報: 営業時間、営業状態
- 評価情報: 評価値、評価数
- その他: 価格帯、写真（最大5枚）、緯度経度

**リクエストパラメータ:**
| パラメータ | 型 | 必須 | 説明 |
|-----------|---|------|------|
| place_id | string | ○ | Google PlaceのID |

**レスポンス例:**
```json
{
  "name": "スターバックスコーヒー 渋谷店",
  "address": "東京都渋谷区...",
  "place_id": "ChIJ...",
  "rating": 4.2,
  "user_ratings_total": 150,
  "opening_hours": ["月曜日: 7:00~22:00", "火曜日: 7:00~22:00", ...],
  "photos": ["https://maps.googleapis.com/..."],
  "latitude": 35.6812,
  "longitude": 139.7671,
  "phone_number": "03-1234-5678",
  "website": "https://...",
  "business_status": "OPERATIONAL",
  "price_level": 2
}
```

## 6. 検索フロー

### 6.1 データフロー図

```
[ユーザー入力]
    ↓
[Map.tsx - インライン検索バー]
    ↓
[useCafeSearch フック]
    ↓
[cafeService]
    ↓
[CafeApiClient]
    ↓
[Backend API (/api/v1/fetch-cafes/)]
    ↓
[Google Places API]
    ↓
[Backend - レスポンス整形]
    ↓
[Frontend - データ受信]
    ↓
[CafeContext - 状態更新]
    ↓
[SearchResultPanel + Map - UI更新]
```

### 6.2 検索処理の流れ

#### 位置情報ベース検索

1. ユーザーが地図を移動
2. 地図の中心座標を取得
3. `searchCafe(lat, lng)` を呼び出し
4. バックエンドAPIにGETリクエスト
5. Google Places API Nearby Searchを実行
6. 結果をフロントエンドに返却
7. `searchResultCafes` に格納
8. マップモードを `MAP_MODES.search` に変更
9. SearchResultPanelと地図マーカーを更新
10. Google Analyticsイベント送信

#### キーワード検索

1. ユーザーがキーワードを入力
2. Enterキーまたは検索ボタンをクリック
3. `searchCafeByKeyword(keyword, lat, lng)` を呼び出し
4. バックエンドAPIにGETリクエスト
5. Google Places API Text Searchを実行
6. 結果をフロントエンドに返却
7. 以降は位置情報ベース検索と同様

### 6.3 状態管理（CafeContext）

**ファイルパス:** `frontend_dev/src/contexts/CafeContext.tsx`

**カフェ関連の状態:**

```typescript
interface CafeContextProps {
```

**マップモード:**

## 8. カフェ登録・削除機能

### 8.1 マイマップへの追加

**サービス層:** `backend/cafemap/services/cafe_services.py:34-65`

**処理フロー:**
1. `create_cafe_and_relation(map_id, cafe_data)` を呼び出し
2. place_idでCafeの存在確認（`get_or_create`）
3. 新規の場合はCafeレコードを作成
4. CafeMapRelationで関連を作成
5. 既存の関連がある場合はエラーを返す

**重複防止:**
- place_idがuniqueのため、同じカフェは1つのみ
- CafeMapRelationで同一マップへの重複登録を防止

### 8.2 マイマップからの削除

**サービス層:** `backend/cafemap/services/cafe_services.py:68-79`

**処理フロー:**
1. `remove_cafe_from_map(user, map_id, cafe_id)` を呼び出し
2. ユーザーのマップ権限を確認（MapUserRelation）
3. CafeMapRelationを削除
4. Cafeレコード自体は残す（他のマップで使用される可能性）

**権限チェック:**
- MapUserRelationでユーザーがマップのオーナーまたは編集権限を持つか確認

## 13. パフォーマンス改善：N+1クエリ問題の解決

### 13.1 問題の概要

#### 改善前の問題点
検索1回あたり、最大**21回のAPIコール**が発生していました。

```
1. 検索APIで20件のplace_idを取得（1回）
2. 各place_idに対して詳細APIを個別に呼び出し（20回）
   ↓
合計: 21回のHTTPリクエスト
```

**影響:**
- レスポンス時間: 2-3秒
- APIコスト: $0.357/検索
- ネットワーク負荷: 高
- ユーザー体験: 遅い

---

### 13.2 解決策：バッチAPIの実装

#### 新規エンドポイント

**`/api/v1/fetch-cafes-details-batch/`**

| 項目 | 内容 |
|------|------|
| メソッド | POST |
| 認証 | 不要 |
| 説明 | 複数のplace_idを一度に処理して詳細情報を返す |

**リクエスト:**

### 13.3 実装の詳細

#### バックエンド実装

**1. 並列処理による高速化**
```python
# backend/cafemap/api/v1/views.py:244-281

import concurrent.futures

def fetch_multiple_cafe_details(place_ids: list) -> list:
    """並列でGoogle Places API Detailsを呼び出す"""
    cafes = []

    # ThreadPoolExecutorで並列処理（最大10スレッド）
    with concurrent.futures.ThreadPoolExecutor(max_workers=10) as executor:
        future_to_place_id = {
            executor.submit(fetch_single_cafe_detail, place_id): place_id
            for place_id in place_ids
        }

        for future in concurrent.futures.as_completed(future_to_place_id):
            try:
                cafe_detail = future.result(timeout=5)
                if cafe_detail:
                    cafes.append(cafe_detail)
            except Exception as e:
                logger.error(f"Error: {e}")
                continue

    return cafes
```

**2. エラーハンドリング**
- 一部のplace_idが失敗しても他は返す
- タイムアウト制御（5秒）
- 詳細なロギング
